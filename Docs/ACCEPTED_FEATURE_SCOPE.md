# 확정 적용 범위 — Classic UX

확정일: 2026-11-08. 사용자 지시: 추천 1·2순위 전체에 커밋 템플릿·이슈 링크·서명 설정, SSH 키·인증 오류 진단, Submodule 탐색·업데이트·상태 안내를 포함한다.

이 문서는 사용자 확정 범위다. 최초 P0/P1 실행 범위를 후속 구현까지 확장하며, SOURCEGIT_CLASSIC_UX_IMPLEMENTATION_PLAN.md의 불변 원칙과 단계별 검증 게이트는 유지한다. 아래 묶음은 제품 우선순위이며 계획서의 P0~P4 단계 번호와 다르다. SourceTree 문서의 지원 유무와 독립적으로 제품 효용을 기준으로 선정했다. 기존 소스가 있다는 사실은 구현 완료·GUI PASS가 아니다.

|---|---|---|
| A01 | File Status → Diff → Stage → Commit | 파일·헝크·라인 선택, stage/unstage, 커밋을 fixture에서 실행하고 Git CLI 상태와 대조 |
| A02 | History 그래프·검색·필터 | 브랜치 범위·검색·커밋 선택·Diff 이동이 일관되며 필터 변경 후 선택 상태가 유효 |
| A03 | 다중 리모트 관리 | 추가·편집·삭제, 기본 리모트, Fetch All, 리모트별 Push URL을 2개 이상 fixture 리모트로 검증 |
| A04 | Fetch/Pull/Push 대상 표시 | 대상 리모트·브랜치·추적 관계를 실행 전에 확인 가능, 잘못된 선택·오류가 숨겨지지 않음 |
| A05 | 브랜치 생성·체크아웃·추적 | 생성·전환·추적 변경과 dirty checkout 보호를 fixture에서 검증 |
| A06 | 충돌 해결 | 충돌 목록 → Diff/외부 도구 → 해결 표시 → 기존 작업 계속/중단 흐름 검증 |

| A09 | 설정·레이아웃 유지 | 창·탭·Splitter·Classic 모드 복원 및 기존 레이아웃 복귀 검증 |

| A11 | Git Flow 설정 조회·변경 | production/develop·접두사 조회 및 변경 가능, 기존 브랜치에 미치는 영향 안내, 임의 브랜치 변경 금지 |
| A12 | 파일 이력·Blame | 파일에서 이력·해당 리비전 내용·Blame에 접근 가능, 선택 대상 일치 |

## 구현 순서

1. 기본 작업 완성: A01~A09 및 A21. 기존 기능 연결과 상태 정합성·실수 방지를 먼저 검증한다.
2. 팀 작업 완성: A10~A17 및 A22. Git Flow는 외부 도구 가용성부터 확인하고 의존성 부재 시 실행 전에 안내한다.
3. 커밋 정책 완성: A18~A20. 커밋 템플릿·이슈 링크·서명을 저장소 설정과 커밋 화면에 연결한다.

모든 묶음은 필수이며 순서는 착수 순서다. 충돌과 파일 소유권에 따라 병렬 조사·독립 파일 구현은 가능하나, 공통 Repository/Preferences/WorkingCopy 수정 및 빌드·GUI는 직렬화한다. 기존 VM·Git 명령·Watcher를 재사용하고, 신규 명령 엔진을 만들지 않는다. 기능별 상세 설계 전에 실제 소스 경계를 확인한다.

## 범위와 검증 제한

- LFS 심화, 커스텀 액션 확장, Subtree, Sparse Checkout, 호스팅 계정 브라우저, 인앱 PR/CI, 단일 리모트 다중 URL, Git Flow bugfix/support, 배포·업데이트 체계는 이번 지시로 필수 승격되지 않았다. 기존 기능은 유지한다.
- 사용자 설정·실제 저장소·계정으로 파괴적 검증을 하지 않는다. 원격 push/PR/배포의 기존 승인 제한은 유지한다. 전송 검증은 로컬 fixture bare 리모트를 사용한다.
- 서명 검증은 전용 테스트 키를 사용하며 사용자 개인키·SSH/토큰/자격증명을 외부 게시하지 않는다. 전역 Git/SSH/agent 설정은 임의 수정하지 않는다.
- 최신 한국어 Debug/Release 빌드는 통과했으나 위 전체 기능군의 완료를 뜻하지 않는다. 기능별 QA 상태는 QA_MATRIX.md에 증거로 기록한다.
- 현재 Orca 최종 문서 보정 task_9caa85c9638b는 agent_readiness timeout 및 unverifiable liveness로 BLOCKED. 이 범위 확정은 워커 복구·모델 대체가 아니다. 기존 파일 소유권이 해제되었다고 추정하지 않는다.
